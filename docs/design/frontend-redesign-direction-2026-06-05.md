> Output of the `frontend-redesign-research` workflow (5 web+code research streams
> — sports-manager UIs, the FM26 backlash, anti-AI-slop identity, dense-data UI,
> our current UI — + Opus synthesis). The design contract for the major frontend
> redesign. Identity thesis: **"the broadsheet and the technical area."**

---

## Visual identity

IDENTITY THESIS — "the broadsheet and the technical area." Final Whistle should read like a serious match-day broadsheet crossed with a pro analyst's terminal, not a SaaS dashboard and not FM26's tile-mobile look. The existing token system already passes the anti-slop bar; the job is to OWN it harder, fix the few generic leaks, and add the one expressive surface (the board) plus chrome that says "real desktop tool with a point of view."

TYPOGRAPHY (keep the three-face stack — it is the single strongest anti-slop asset; do NOT swap to Inter-only). Anton = display ONLY (wordmark, scorelines, the big match clock, section titles like "Events"/"Standings", competition names). JetBrains Mono = every number you scan vertically and every technical surface (table cells, league points/GD, wages, fees, minute markers, the match clock digits, seeds/hashes on /dev). Inter = prose only (commentary, scout reports, press copy, staff advice, NPC dialog). The hard rule that earns Inter the right to stay: Inter never appears in display or numeric contexts. Tighten Inter further — `font-variant-numeric: tabular-nums` is already global; add `letter-spacing: -0.006em` on body prose and keep the 14px/1.25rem base. Recommendation: do NOT introduce a fourth face now; if a future pass wants sharper identity, the highest-value single change is replacing Inter-body with a less-saturated grotesque (Space Grotesk or Geist) — flagged as an open question, not a commitment.

PALETTE (keep pitch/ink/paper/midnight; ration the accent; kill the two leaks). Signature accent stays pitch-500 #2d6e3e — muted club-color green, rationed to exactly ONE primary action per screen + active-nav + the live-match highlight. It must never read as video-game grass; that is precisely why the board's bright green-600 must die (see below). Neutrals: paper (warm ivory) for light, midnight 4-step for dark — both stay as-is, both first-class. Two state colors only: flag-yellow #f5c84b (caution: contract expiring, booking, borderline form) and flag-red #c8412c (danger: error, red card, over-budget). FIX: replace every `rose-600/rose-400` (Match.tsx frame-load notice, line ~687) with `flag-red` so error states are consistent everywhere — there must be exactly one red token. FIX the board surface: the PixiJS pitch is the ONE place the muted identity breaks (`PITCH_COLOR = 0x16a34a`, home `0x2563eb`, away `0xf59e0b` are raw Tailwind defaults — pure slop). Re-derive board colors from the token table: pitch canvas = a desaturated dark turf that sits with pitch-700/800 in dark mode and a muted pitch-600 in light, NOT bright green-600; home dots = pitch-300 or the managed-club accent; away dots = a single contrasting neutral-amber pulled into the token set (`board.away`), ball = paper-white with a thin ink ring so it reads on light turf. Add a `surface.board` token rather than reusing `bg-pitch-600`.

DENSITY POSTURE — lean dense, FM-CLASSIC, explicitly NOT FM26. Default row height 28-32px (the DataTable's `px-2 py-1` is right; keep it). Tables are the default for every working screen (Squad, League, Transfers, Stats lists); cards/tiles are allowed ONLY on the Home/Hub summary layer. Numbers are shown as numbers — never a bar or star hiding a value, never FM26's verbal-only "Reasonable/Competent/Outstanding" staff ratings (that is the explicit anti-pattern). Where the design philosophy is "labels carry meaning" (player ability surfaced as "Reads the game well" instead of 17/20), the label is a deliberate controlled-vocabulary choice tied to the no-visible-stats design pillar — but it must be applied with a consistent 5-7 tier scale, and any future numeric must stay one hover away, never two clicks.

MOTION — fast, functional, forgettable. 150-200ms ease-out for entering, ease-in for exiting, no page-load entrance animations (content is there, not arriving). Hover confirms interactivity in ~100ms. The board scrubber runs on the Pixi ticker / rAF, never CSS transitions (already correct). Honor the existing `.reduce-motion` class and `prefers-reduced-motion`. Test: if the task works without the animation, cut it.

WINDOW CHROME — the highest-leverage identity move not yet built. Adopt a custom Tauri titlebar (`decorations: false` + `data-tauri-drag-region`) carrying, left-to-right: FINAL WHISTLE wordmark (Anton, small) with a managed-club accent swatch, then the season/competition context (e.g. "Season 3 · Premier Division"), then native-style window controls. This single strip immediately distinguishes the app from every Electron/shadcn dashboard and replaces the developer StatusBar diagnostic ("determinism: pinned · build: dev") which must move to /dev only.

TEXTURE — a whisper, not a shout. A 4-6% SVG feTurbulence/CSS noise on the sidebar, the match-day header bar, and the board surround only — never on text-bearing tables. Elevation stays line-based (1px ink-mute/15 light, midnight-line dark), shadows stay near-invisible (`shadow-panel`); this is the Bloomberg-terminal signal, not Notion cards.

## Component system

SHELL / NAV — fix the FM26 mistake before it happens: ship a PERSISTENT VERTICAL SIDEBAR as the primary nav, not the current horizontal TopBar. The single clearest lesson from the FM26 backlash is that removing the always-visible left sidebar destroyed spatial memory and trust even when the sim improved. So: a fixed w-56 left rail listing every management domain (Hub/Home, Squad, Tactics, Training, Transfers, League, Career, Reports/Stats) always visible, never a hamburger, never hover-only submenus (FM26's six top-bar dropdowns are the anti-pattern). The current Layout already has a w-56 aside used for career context — promote it to the real nav and move the career context (managed club, season, next fixture) into a card BELOW the nav links. Compose: SolidJS `<For>` over a `NAV` array, `<A activeClass="active">` reusing `.fw-nav-link`. Keep the custom titlebar as the top strip (replacing TopBar). Footer micro-strip for save state. REMOVE the inline `[1]`-`[M]` hotkey spans from labels NOW — they are decorative noise until T4-6b wires real keys; when keys land, surface them as a discoverable shortcut overlay (press `?`), not permanent label clutter. Honor the `Next fixture: —` honesty rule: render that slot only when a career is active and data exists; otherwise omit it (a permanent em-dash is a broken promise).

THE INBOX IS THE HEARTBEAT (new, the missing core-loop screen). The Hub/Home for an ACTIVE career is an inbox-anchored dashboard: a one-glance "Bite" header (league position + form string + next fixture countdown), then a reverse-chronological action feed where "Must Respond" items carry a flag-red left border and block time-advance. This is the authoritative "what do I do now," with everything else as reference. Distinct from the pre-career Home (main menu) which keeps full-screen ownership (wordmark, New Career / Load Save) and must NOT show the management chrome.

TABLE SYSTEM (evolve DataTable, do not replace it). Keep the no-zebra, thin-border, mono-numeric base. Add, in priority order: (1) right-align numeric columns / left-align text (hard binary rule — currently every cell is uniformly mono-left, which fights vertical magnitude scanning); (2) sticky header + left-pinned identifier column (player/club name is always column 1, never a rank or checkbox) via TanStack v8 column pinning + CSS sticky; (3) row virtualization (TanStack Virtual, 10-row overscan) for any list >50 rows; (4) header groups / spanning headers for wide squad tables ("Form & Fitness", "Contract", "Role Suitability"); (5) a VIEWS switcher (OOTP model) — saved named column presets per list type (Attributes / Contract & Wages / Form & Condition / Position & Role / Scouting Grade) that swap the column set instantly with no navigation; (6) a context menu on every named entity (right-click a player/club → view profile, shortlist, scout, offer, loan) so the user never loses table position to act; (7) group-gap spacing (an 8px divider between position groups or top-4/rest) instead of zebra. Sparklines (form, minutes, wage trend) live inline in cells as minimal ECharts or tiny SVG paths, no axes, 60-80px wide, value on hover.

CARD / PANEL SYSTEM — keep `.fw-panel` as the surface primitive. Cards are ONLY for the Hub summary tier and single-entity focus (player profile drawer). Adopt the SGX "Bite / Snack / Meal" progressive-DISCLOSURE (never progressive-hiding — FM26's tile-expand model is banned): summary bar (Bite, always visible) → sortable table (Snack, the workspace) → detail drawer or expanded row (Meal, on demand). Player profile = right-side drawer (preserves table context) for the 2-3 line summary, full route only when the profile is itself the task. Financial/Transfer screens lead with a sticky summary bar above the table (wage bill / budget / headroom — the Bite) — never put the budget inside the table.

THE MATCH SURFACE — promote it from a developer sandbox to the emotional payoff "war room," and split dev from player. The current /match is a dev tool (raw seed/hex input, tick count, blake3 hash in the commentary aside) wired into primary nav — that must move to /dev/match. The player-facing match is a PAUSE-AND-DECIDE three-zone layout (football has natural pauses; do NOT build a live always-on dashboard like Motorsport Manager): (Zone A) the 2D board as the spatial map — re-themed off tokens, responsive width (kill the hardcoded 840px; size to a max-w container with aspect-ratio so it scales to viewport); (Zone B, primary read) the commentary feed carrying full information weight — reverse-chronological newest-on-top, fixed-width mono minute marker, event-type badge column, Inter prose flowing right, goal/red-card rows highlighted; the feed must be legible enough to manage with the board hidden (FM's commentary-only mode is the proof this surface is primary, not decorative); (Zone C) a player strip (XI condition/rating) plus a backroom-advice panel that gives OPINIONATED football-language advice ("they're exploiting the gap behind your right back") with the numbers one expand away — never a raw xG dump. Touchline-equivalent controls (mentality/shape/quick sub) stay ON-SCREEN as primary actions during pauses — keeping match agency on-screen is the explicit FM26-shouts-removal lesson. Compose with Solid signals for match state, the existing lazy-loaded PixiJS board for Zone A, and the existing event/commentary memos (filtered) for Zone B.

## Anti-AI-slop rules (the do-NOT list)

- NO indigo/purple/blue accent and NO purple-to-blue gradients anywhere — the single most reliable AI-slop tell. Signature accent is pitch-500 only.
- NO untouched shadcn/Tailwind defaults: no 8px+ (rounded-lg/xl/full) radii except functional pills; stay on the 2px/4px scale. No default `border` gray — use ink-mute/15 (light) and midnight-line (dark).
- NO bright video-game grass: replace the board's `0x16a34a` pitch, `0x2563eb` home, `0xf59e0b` away with token-derived muted turf + accent dots + a `surface.board`/`board.away` token. This is the one surface that currently leaks raw Tailwind hex.
- EXACTLY ONE red token. Delete every `rose-600/rose-400` (Match.tsx frame-load notice) and use flag-red. Two competing error reds is an unowned-default tell.
- NO Inter in display or numeric contexts — Inter is body-prose only; Anton for display, JetBrains Mono for all numbers. This is what earns Inter the right to stay in the stack.
- NO three-column icon+heading+copy card grids, NO centered hero+CTA+emoji marketing layout, NO emoji anywhere in UI or copy.
- NO whitespace-as-feature: do NOT loosen FM-class density toward FM26 bloat. Keep 28-32px rows, 14px base, thin lines. Sparse = 'nothing to say'; density = 'serious tool.'
- NEVER hide a number behind a bar/star/icon with no accessible value, and NEVER ship FM26's verbal-only staff ratings ('Reasonable/Competent/Outstanding') with no number reachable. Where the design surfaces ability as a label (no-visible-stats pillar), use a consistent controlled vocabulary, not vague adjectives.
- NO tile-and-card working screens and NO progressive-HIDING (data behind expand-tiles). Tables for comparison/sorting; cards only for Hub summary + single-entity focus. Progressive DISCLOSURE only.
- NEVER remove the persistent sidebar, never collapse nav into a hamburger or hover-only top-bar dropdowns (the FM26 navigation regression).
- NO developer diagnostics in player-facing chrome: move seed/hex/tick inputs, blake3 hashes, and the 'determinism: pinned · build: dev' StatusBar to /dev/* only.
- NO decorative hotkey hints in nav labels before keys are wired; NO permanent placeholder em-dashes ('Next fixture: —') — render a slot only when it has live data.
- NO generic dashboard chart-icons, trophy emojis, or football-with-swoosh sports-app graphics. The 2D board is the only expressive visual; identity comes from football-native content (role abbreviations, formation notation, pitch-zone terms), not decoration.
- NO entrance animations on page load; NO hover/micro-interactions that exist to show off. Motion is 150-200ms, functional, removable-without-loss, and respects reduce-motion.
- NO banned mystical state-nouns or stat-delta callouts, and NO marketing-speak — football-native vocabulary only, per the banned-terms lint (catalog: docs/design/ui-vocabulary.md).

## Implementation plan (phased)

1. PHASE 0 — Token + foundation pass (no screen rewrites, unblocks everything, does not touch the match-sim work). Add the missing tokens: `surface.board` (muted turf, light+dark), `board.home`/`board.away`/`board.ball` derived from the palette, and ensure flag-red is the sole error token. Add the 4-6% noise texture utility (sidebar/header/board-surround only). Add `letter-spacing` tightening on Inter body. Ship as a tailwind.config.ts + styles.css diff with a screenshot via the Playwright harness. Self-contained; mergeable alone.
2. PHASE 1 — App shell. Build the custom Tauri titlebar (decorations:false + data-tauri-drag-region; verify capabilities/default.json least-privilege). Convert Layout to a persistent left sidebar nav; move career-context into a card below nav; delete the `[1]`-`[M]` hotkey spans; gate the 'Next fixture' slot on live data; move the StatusBar dev diagnostic to /dev. Reuse .fw-nav-link. This is the chrome every later screen composes inside.
3. PHASE 2 — Re-theme the TacticalBoard component OFF tokens (kill 0x16a34a/0x2563eb/0xf59e0b in pitch-coords.ts), make canvas width responsive (max-w container + aspect-ratio, drop the hardcoded 840px), keep the Pixi-once lifecycle and ticker loop intact. This is a contained visual fix that does NOT block the watchable-match sim work happening in Lane A — the board reads whatever frames the sim emits; we only change colors + sizing + container, never the frame contract.
4. PHASE 3 — DataTable upgrades as a shared-primitive PR: right-align numeric / left-align text, sticky header + left-pinned identifier, TanStack Virtual (10-row overscan), header groups, group-gap spacing, and the entity context-menu primitive. Land the Views switcher (saved column presets, per-machine persistence) as a follow-on slice. Each ships independently; League/Squad inherit them.
5. PHASE 4 — Player-facing Match screen. Three-zone pause-and-decide layout: re-themed board (Zone A), commentary-as-primary feed reverse-chronological with mono minute markers + badge column (Zone B), player strip + opinionated backroom-advice panel (Zone C). Move all dev controls (seed/ticks/hash) to /dev/match. On-screen touchline-equivalent controls as primary actions. Depends on Phases 0-2; can land incrementally (feed + board first, advice panel second, controls third) so it never blocks the sim's watchable-match milestone.
6. PHASE 5 — Hub/Inbox dashboard (active-career home) with Bite header + Must-Respond action feed (flag-red blocking items), and split the pre-career main-menu Home to own the full screen without management chrome.
7. PHASE 6 — Screen re-skins onto the finished system in priority order: League (showcase density + form sparklines + managed-club accent row), Squad (Views + header groups + context menu + drawer), then Transfers (sticky financial Bite-bar) + Player drawer, Tactics, and finally Stats + Settings (+ shortcut overlay on `?`).

## Open questions (owner)

- Body face: keep Inter (defensible because Anton + JetBrains Mono carry identity and Inter never touches display/numeric surfaces) or invest one pass swapping it to a less-saturated grotesque (Space Grotesk / Geist) for sharper identity? This is the single highest-value identity change available but it is a taste call, not a correctness one.
- Default theme: light (warm paper, broadsheet feel — current default) or dark (midnight, Bloomberg-terminal feel, less eye-strain over 300-hour saves, and dark backgrounds give more high-contrast color headroom)? The dense-data research leans dark-default; the existing identity leans warm-paper. Which is the brand?
- Managed-club accent: should the signature accent stay fixed at pitch-500 globally, or should the user's chosen club tint the titlebar swatch + active-nav + match highlights with a per-club accent color (a procedural-world identity hook)? If yes, we need a club-accent token pipeline and a guard that the club color never collides with flag-red/flag-yellow state cues.
- No-visible-stats vs power-user stack-ranking: the design pillar surfaces ability as labels ('Reads the game well'), but the FM26 lesson is that verbal-only ratings destroy stack-ranking. Where is the line — are scout grades / form / condition allowed to be numeric tiers the user can sort on, while raw attributes stay label-only? This needs an owner ruling because it shapes every table.
- Board re-theme palette: should the away side be a neutral amber/ochre (broadcast convention) or a second muted-neutral so the board never competes with pitch-green? And does the pitch canvas go dark-turf in both themes for consistency, or follow the light/dark theme?
- Match pacing model: confirm the pause-and-decide rhythm (interruption windows at goals/cards/set-pieces/half-time + on-demand) over a Motorsport-Manager always-on live dashboard. Research strongly recommends pause-and-decide for football, but it's a core product-feel decision worth the owner's explicit sign-off.
