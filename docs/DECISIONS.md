- **2026-05-13** — ADR-0002 Player attribute model (Proposed): 55-attribute schema at `docs/adr/0002-player-attribute-model.md`. 38 visible (14 technical / 10 mental / 8 physical / 6 goalkeeper-specific, all on a flat struct so BT decision sites never branch on role) + 17 hidden (14 personality + 3 durability). - **2026-05-13** — ADR-0005 Memory ledger + breakthroughs (Proposed): 14-field MemoryEvent schema + 28-event catalogue at `docs/adr/0005-memory-ledger-and-breakthroughs.md`. Both `stakes` and `salience` are `Q32` (not f32 as DESIGN_DOC §7 implied). Three decay functions (Never / Linear / Exponential), applied at read-time projection only; ledger is never mutated. Five readers (Salience / Press / Fan / Scout / Coach) with explicit cadences. Breakthroughs require all three: per-(player, attribute_family) `signature_readiness` threshold + narrative-gating event + per-family cooldown — PA redraws upward, partial CA lift via `ca_lift_fraction`. Regressive collapse is the symmetric mechanism (`regressive_pressure` ticker; PA down to a career-floor; reversible only via subsequent breakthroughs). Mod compatibility via `UnknownEventClass { tag: ModEventTag, payload: Vec<u8> }` variant — opaque bytes participate in canonical BLAKE3 hash but are ignored by core readers. Context: pillars 2 and 3 both load-bearing here; research wave 1 (RimWorld memory-as-decaying-thoughts; CK3 hidden traits) informed the decay + bias-vector patterns. Supersedes: DESIGN_DOC §7's `stakes: f32` and `salience: f32` typing (architecturally wrong, would have broken cross-OS canonical hash if implemented as written).

- **2026-05-13** — ADR-0006 BT vs FSM for per-player decision layer (Proposed): hybrid **FSM-of-Behavior-Trees** at `docs/adr/0006-bt-vs-fsm-decision-layer.md`. Outfield roles (defender / midfielder / forward) each have a flat enum of ~6-10 coarse role states; each state owns a small BT (~10-30 leaves) that runs per tick. Goalkeeper is pure FSM, no inner BT — GK behavior is mode-dominated. Role-state transitions are short priority-ordered `(predicate, target_state)` lists evaluated at dispatch. Universal pre-emption hooks are defined once at the dispatcher (single-chaser claim, foul reaction, set-piece switchover) — this fixes ZOXEXIVO's 2,141-line state-files problem. Utility-scored selector nodes are a first-class BT node type fired at on-ball decisions; personality bias multiplies in at utility scores + probabilistic BT decorators, never into role-state transitions. Authorship split: role-state catalogue + pre-emption hooks + BT leaf primitives are Rust in `fw-match-sim`; the BT subtrees themselves are content-pack RON (schema-versioned, FW-VAL'd). Nodes are code, trees are data. Context: pure-BT was the research-wave recommendation under the (now-retracted) LoC budget; reframe reopened the question on architectural merit. Hybrid keeps FSM's debuggability + BT's composability + Halo-style data-driven authoring. Supersedes: the pure-BT layer-2 recommendation in `docs/research/sports-sims/00-synthesis.md` (was budget-driven; retracted today).
